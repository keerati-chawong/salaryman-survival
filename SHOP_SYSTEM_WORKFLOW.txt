SALARYMAN SURVIVAL - SHOP & COIN ECONOMY
Implementation workflow / reference document
==========================================================

This document explains the shop, coin economy, and inventory ("backpack")
system built into the game: what was built, why, how it works, and known
caveats for whoever picks this up next.


1. GOAL
----------------------------------------------------------------------
Turn the empty Shop.tscn scene (a background image with nothing on it) into
a working shop: a coin currency the player earns from winning fights and
spends on consumable items, plus a way to use those items during Battle.

The scaffolding for coins already existed before this work started
(GameState.coins, GameData.ENEMIES' coin_reward, Battle.gd awarding coins on
a win) - this work is what actually made coins spendable and items usable.


2. THE COIN ECONOMY
----------------------------------------------------------------------
Earning:
  - Winning a Battle awards coins. The amount is per-enemy, set by
    GameData.ENEMIES[i]["coin_reward"]:
      Rookie 15 / Work-Dodger 20 / Team Lead 30 / HR 35 / CEO 60
  - Awarded in Battle.gd's _win().

Spending:
  - GameState.spend_coins(amount) / GameState.add_coins(amount) already
    existed; the Shop screen is the only place that calls spend_coins().

Visibility (this was a specific ask - "make money easy to see"):
  - Shop.gd shows a large, always-visible coin counter with a coin icon in
    its top bar, plus a "-N" flash near it on every purchase.
  - Battle.tscn's player panel now also has a permanent coin counter (see
    section 6) so the balance is visible during fights too, not just in
    the shop.
  - The win screen shows a large "+N COINS" pop (see section 6) instead of
    silently crediting the total.


3. ITEM DATA MODEL (scripts/GameData.gd)
----------------------------------------------------------------------
GameData.ITEMS is a Dictionary of 9 items, each a Dictionary with:
  name, blurb, effect ("anger" | "hp" | "guard"), amount, price, icon (path)

The 8 food/drink items were chosen to match the vending machine artwork
(see section 4) and split evenly between the two useful effects:

  Anger (used to power word-attacks in Battle):
    coffee      +45 Anger   15 coins
    energy_bar  +30 Anger   12 coins
    soda        +50 Anger   22 coins
    banana      +20 Anger    8 coins

  Patience (the player's HP):
    apple       +35 Patience  12 coins
    water       +30 Patience  10 coins
    noodles     +80 Patience  24 coins
    sandwich    +65 Patience  20 coins

  Accessory (not part of the vending machine art):
    headphones  Guard (halves next hit)   35 coins

Design note: the original build only had 3 items (coffee/bubble_tea/
headphones). Expanding to 9 was a deliberate scope decision made with the
project owner mid-session (bubble_tea was retired in favour of the 8
vending-machine items; headphones was kept as a separate accessory since it
has no matching icon in the machine's artwork).


4. ASSET PIPELINE (assets/item/)
----------------------------------------------------------------------
The 8 food/drink icons were sliced out of assets/item/"item asset.png" (a
large multi-item sprite sheet), and their positions on the vending machine
background (assets/backgrounds/shop.png) were measured, using a Python
script (Pillow + scipy + OpenCV, run one-off, not part of the game/build):

  1. scipy.ndimage.label() found each sprite's bounding box on the sheet by
     connected-component analysis of its alpha channel.
  2. Each box was cropped out (with a small padding) and saved as
     assets/item/icon_<name>.png (icon_coffee.png, icon_noodles.png, etc).
  3. OpenCV template matching (cv2.matchTemplate, multi-scale) found where
     each of those 8 icons is painted onto assets/backgrounds/shop.png's
     vending machine display, giving pixel-accurate rects for the clickable
     hotspots used in Shop.gd (see FOOD_SLOTS below).

headphone.png was supplied directly (not sliced) and used as-is.

coin.png (already present) is the coin icon used throughout the UI.


5. SHOP SCENE (scripts/Shop.gd, scenes/Shop.tscn)
----------------------------------------------------------------------
scenes/Shop.tscn itself only contains the background image and the script;
everything else is built at runtime in Shop.gd's _ready(). (See section 8,
"Known caveat", for why this isn't how it would normally be done.)

Vending machine hotspots:
  - FOOD_SLOTS is a Dictionary of id -> Rect2, in the *source art's* pixel
    coordinates (the background art is painted at 2528x1686 but shown in
    the 1536x1024 game viewport), measured via the OpenCV step above.
  - ART_SCALE = 1536.0 / 2528.0 converts those rects into game-screen
    coordinates.
  - For each of the 8 items, an invisible flat Button is placed over its
    icon on the machine art (with a little extra padding for an easier
    click target).
  - Hover: the slot brightens (tint) and a floating tag appears above it
    showing name / effect / price.
  - Click: buys immediately (GameState.spend_coins + grant_item), no
    confirmation step, matching how a real vending machine works.

Accessories row: headphones (not part of the machine art) gets its own
row with an icon, price, and an explicit Buy button, since there's nowhere
on the background to click for it.

"Your Bag" panel: lists every item (icon + name + effect blurb + how many
you're carrying), refreshed live off GameState.stats_changed. This directly
answers "what does this thing I bought actually do" at a glance.

Top bar: title, large coin counter (icon + number), Back button (returns to
Promotion.tscn, since that's the only place that links to the shop).


6. BATTLE SCENE CHANGES (scripts/Battle.gd, scenes/Battle.tscn)
----------------------------------------------------------------------
Two changes were needed once the item list grew from 3 to 9:

a) Item usage -> "Backpack" popup
   The old design was a single row of item buttons - fine for 3 items, but
   9 doesn't fit. ActionPanel's ItemRow now holds one "Open Backpack (N
   items)" button. Pressing it opens a modal (dim background + panel) with
   a 5-column grid of all 9 items as icon+count slots; clicking a slot uses
   that item and closes the modal. Esc closes the modal instead of quitting
   to the menu while it's open.

b) Coin counter
   PlayerPanel now has a coin icon + count next to the Rank label
   (PlayerPanel/Cols/Bars/BottomRow), kept in sync in _refresh().

c) Win-screen coin animation
   Originally the "+N coins" on a win reused the same small popup used for
   ordinary damage numbers (fades out in 0.75s, then the screen just sat
   there for another second doing nothing before the scene changed - too
   fast to read). Replaced with _show_coin_reward(): a large 64pt label
   that scales in with a bounce, holds for ~1.2s, then fades - about 2
   seconds total. The wait before advancing to Promotion was bumped from
   1.8s to 2.2s to match.


7. GameState.gd CHANGES
----------------------------------------------------------------------
Inventory handling was generalized from 3 hardcoded keys (coffee,
bubble_tea, headphones) to looping over GameData.ITEMS, so adding/removing
an item in GameData.gd doesn't require touching GameState.gd:
  - _default_inventory() builds a zeroed dict for every id in GameData.ITEMS,
    then tops up a small starter kit (1 coffee, 1 water, 1 headphones).
  - load_game() rebuilds the same way and only overwrites ids that exist in
    a saved file, so an old save missing new item ids just defaults to 0
    instead of erroring.
  - advance_stage()'s stage-clear reward grants coffee + water (replacing
    the retired bubble_tea).


8. BUGS FOUND AND FIXED DURING THIS WORK
----------------------------------------------------------------------
a) Item icons rendering as tiny unrecognizable slivers in Battle's old
   item row. Root cause: Button.icon at a ~58px button width, squeezed by
   Button's built-in icon+text layout. Fixed by moving to the Backpack
   modal with hand-composed slots (a plain Button with a child TextureRect
   + Label instead of relying on Button.icon).

b) Backpack icons then rendering WAY oversized, spilling out of their
   slots. Root cause: TextureRect.texture was assigned before
   TextureRect.expand_mode was changed from its default (EXPAND_KEEP_SIZE)
   to EXPAND_IGNORE_SIZE. Assigning the texture while still on
   EXPAND_KEEP_SIZE immediately locks the node's minimum size to the full
   source image (up to 529x378 for headphones); setting a smaller .size
   right after gets silently clamped back up to that stale minimum, and
   because the icon's parent is a plain Button (not a Container), nothing
   ever re-lays it out afterward. Fix: always set expand_mode/stretch_mode
   BEFORE assigning .texture. Applied everywhere icons are built (Battle.gd
   and Shop.gd) as a defensive rule, not just where it was visibly broken.

c) Backpack item hover showed no tooltip. Root cause: the modal is drawn on
   top of ActionPanel, so the hover handler was updating the HintLabel that
   lives *behind* the modal - technically working, just invisible. Fixed by
   giving the backpack modal its own hint line inside the panel.

d) Coin-reward animation was unreadable (see section 6c).


9. KNOWN CAVEAT - HOW THE UI WAS BUILT
----------------------------------------------------------------------
Shop.gd and Battle.gd's backpack overlay build their entire static layout
(panels, positions, sizes) in GDScript at runtime, rather than as nodes
laid out in the .tscn scene file the way the rest of this project does it
(e.g. Promotion.tscn, OptionsMenu's static chrome). This was done without
access to the Godot editor in the environment this work was done in, so
there was no way to drag-and-drop/visually arrange nodes - the entire
"scene" had to be expressed as code instead.

This works, but it's not idiomatic for a fixed layout like this, and it's
harder to tweak visually (every position is a hardcoded Vector2 in a
script instead of something you can drag in the inspector). The project
owner flagged this as looking unusual, correctly.

Recommended follow-up: move the static structure (panels, labels,
containers, the backpack's dim/close/title) into Shop.tscn and Battle.tscn
as real nodes, editable in the Godot inspector, and leave only the
genuinely dynamic parts in script - the per-item loops that build one
row/slot per entry in GameData.ITEMS (vending hotspots still need to stay
in code since their positions come from measured pixel coordinates, not a
container layout).
